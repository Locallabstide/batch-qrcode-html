1项目概览

这是一个把「一张两列表格」批量转成「一堆带样式二维码图片」的纯前端工具。打包成单个 HTML 文件，双击即用，无需服务器、无需联网、无需安装任何依赖。

能力边界

维度说明
输入两列数据：{name, content}。来源：手动文本、.xlsx / .csv / .txt 导入
核心纯 JS 实现的 QR 生成内核（版本 1–40，UTF-8，L/M/Q/H，8 掩码择优）
样式尺寸、静区、前景/背景色、圆点样式、LOGO（10–25%）、上/下展示文字
输出PNG / JPG / SVG，单张下载或打包 ZIP
运行环境Chromium 103+ / Safari 16.4+ / Firefox 113+（依赖 CompressionStream）

2设计原则与约束

  1. 零依赖 —— 不引任何 CDN、npm 包。SheetJS、qrcode.js 这类常见库全部自研替代。
  2. 单文件 —— 一个 .html 即完整产品，方便通过邮件/U 盘分发，双击即用。
  3. 纯离线 —— 不发起任何网络请求，数据不离开本机。可断网验证。
  4. IIFE + 严格模式 —— 全部逻辑包在一个立即执行函数里，避免污染全局；"use strict" 强制显式声明。
  5. 渐进增强 —— CompressionStream 缺失时 ZIP 回退「存储模式」，功能不中断（仅体积变大）。
  6. 能力透明 —— UI 文案与代码行为严格一致；不支持的组合（如 SVG 不含 LOGO）要在界面上明说。
为什么不用现成库？ 因为是「单文件离线分发」场景：引 CDN 会破坏离线；内联大库会显著增大文件体积并引入不必要的依赖面。自研 + 按需实现是这里的最优解。

两列数据模型（架构要点）

state.data 是 {name, content} 对象数组，而非字符串数组。这一点贯穿所有模块：

  • parseTextRows / parseCsvRows / readXlsxRows → 产出 {name, content}[]
  • fileNameFor(row, idx) → 依 row.name 或命名策略生成文件名
  • getTextFor(row, st) → 依文字来源返回展示文字
  • renderCanvas(row, st, scale) / renderSVG(row, st) → 接收 row 而非纯字符串

数据流（单向）

textarea.value
   │  parseTextRows()          // 唯一解析入口
   ▼
state.data ──┬─→ renderList()    // 文件清单
             ├─→ updateStats()   // 统计（重复/超长/缺内容）

5QR 生成内核

PART 1 是一个完整的 QR Code 生成器，思路参考 Nayuki 的算法结构，用纯 JS 重写。

5.1 GF(256) 有限域运算

// 预计算 exp/log 表，把乘法转成加法（查表）
const GF_EXP = new Uint8Array(512), GF_LOG = new Uint8Array(256);
(function(){
  let x = 1;
  for(let i = 0; i < 255; i++){
    GF_EXP[i] = x; GF_LOG[x] = i;
    x <<= 1; if(x & 0x100) x ^= 0x11D;   // 本原多项式 x^8+x^4+x^3+x^2+1
  }
  for(let i = 255; i < 512; i++) GF_EXP[i] = GF_EXP[i - 255];
})();

5.2 容量表（关键数据）

两张 41×4 的常量表，取自 ISO/IEC 18004 官方数据：

  • ECC_CODEWORDS_PER_BLOCK[ver][eclIdx] —— 每块的纠错码字数
  • NUM_ERROR_CORRECTION_BLOCKS[ver][eclIdx] —— 纠错块数
function getNumDataCodewords(ver, ecl){
  return Math.floor(getNumRawDataModules(ver) / 8)
    - ECC_CODEWORDS_PER_BLOCK[ver][idx] * NUM_ERROR_CORRECTION_BLOCKS[ver][idx];
}
⚠️ 曾经踩过的坑（务必引以为戒）： 最初把 ECC_CODEWORDS_PER_BLOCK 手工误抄成了「每版本纠错码字总数」而非「每块纠错码字数」。结果 getNumDataCodewords 在版本 ≥ 10 时返回负数，高版本全部生成失败。
正确做法： 这类 40×4 的常量表绝不手工转录，应从权威来源机读提取，并用公式自校验：
rawCw − ECC×blocks === totalData（160 组全部成立才算通过）。

5.3 分段编码

按内容自动选择最省的模式：

模式判定每字符位宽
数字 Numeric纯数字10 / 7 / 4（按 3/2/1 位分组）
字母数字 Alnum仅 0-9 A-Z $%*+-./:11 / 6
字节 Bytes其余（含中文）UTF-8，每字节 8 位

关键函数：isNumeric / isAlnum / makeSegments / getTotalBits / numCharCountBits。

5.4 纠错与交织

addEccAndInterleave 对每块数据计算 Reed-Solomon 纠错码，然后按列交织（interleave）成最终码字序列。配套函数：rsGenPoly、rsComputeDivisor、rsComputeRemainder。

5.5 矩阵构建与掩码

依次放置：定位图案（三个角）→ 校正图案 → 时序图案 → 格式信息 → 版本信息 → 数据。生成 8 种掩码各算惩罚分（PENALTY_*），选最低分的那个。

5.6 对外接口

function generateQR(text, ecl) → {
  version,          // 1–40
  size,             // 模块边长 = version*4 + 17
  mask,             // 选中的掩码 0–7
  getModule(x, y)   // → true(黑) / false(白)
};
内核是纯函数：同样的 (text, ecl) 一定得到同样的矩阵，无副作用、无全局状态。这使它可以被单独提取出来做 Node 端测试。

6数据解析与 CSV 往返

6.1 解析入口 parseTextRows

把 textarea 的纯文本转成 {name, content}[]。分隔符优先级：Tab > 逗号 > 整行即内容。

function parseTextRows(text){
  const lines = splitCsvLines(text);   // ← 引号感知的行切分
  for(const line of lines){
    if(line.indexOf("\t") >= 0){      // Tab 优先
      const p = line.split("\t");
      name = p[0].trim(); content = p.slice(1).join("\t").trim();
    }else if(line.indexOf(",") >= 0){ // 逗号次之
      const cells = splitCsvLine(line);
      name = cells[0].trim(); content = cells.slice(1).join(",").trim();
    }else{ content = line.trim(); }   // 单列 → 全部当内容
  }
}

6.2 两个 CSV 工具函数

函数作用
splitCsvLine(line, delim)单行按分隔符切分，正确处理引号内的分隔符与 "" 转义
csvQuote(s)写回文本时给含 , " \n 的字段加引号并转义
关键坑：引号内的换行。 早期版本直接 text.split("\n") 切行 —— 结果一个单元格内容里若含换行，会被拆成两行，数据静默损坏。正确做法是先做引号感知的行切分： 
function splitCsvLines(text){
  const out = []; let cur = "", inQ = false;
  for(let i = 0; i < text.length; i++){
    const c = text[i];
    if(c === '"'){ inQ = !inQ; cur += c; }
    else if((c === "\n" || c === "\r") && !inQ){
      out.push(cur); cur = "";
      if(c === "\r" && text[i+1] === "\n") i++;  // 吃掉 \r\n
    }else cur += c;
  }
  out.push(cur); return out;
}

6.3 往返对称性（不变量）

必须满足：parseTextRows(setRowsToText(rows)) === rows。setRowsToText 要给名称和内容都做引号转义（早期只转义了内容，导致名称含逗号时结构被破坏）。

已实测的往返用例（全部通过）： 普通、名称含逗号、内容含逗号、名称含引号、内容含换行、中文+逗号。

7xlsx 轻量解析

.xlsx 本质是个 ZIP。解析流程不依赖 SheetJS：

file.arrayBuffer()
   ▼  unzip()              // 解析 ZIP 中央目录，取所需条目
   ▼  inflateRaw()         // 用原生 DecompressionStream('deflate-raw') 解压
   ├─ xl/sharedStrings.xml → parseSharedStrings()  // 共享字符串表
   └─ xl/worksheets/sheet1.xml → parseSheet()      // 单元格
   ▼  readXlsxRows()       // → [{name, content}]，跳表头

关键点

  • 中央目录解析：readU16 / readU32 按 PKZIP 结构定位每个条目的本地头与数据段
  • 解压：inflateRaw 用浏览器原生 DecompressionStream('deflate-raw')；method=0 时直接用原始字节
  • 单元格类型：s（共享字符串）、inlineStr（内联）、b（布尔）、其他按数字处理
  • 列号换算：colToIndex("AB12") → {col, row}
  • XML 反转义：unescapeXml 处理 &lt; / &#38; / &#x26; 等
  • 自动跳表头：readXlsxRows(file, skipHeader)

8渲染管线（Canvas / SVG）

8.1 布局计算 layoutMetrics

function layoutMetrics(qr, st, textLine){
  const modules   = qr.size + st.quietZone * 2;   // 模块数（含静区）
  const modulePx  = st.sizePx / modules;          // 每模块像素
  const textPx    = textLine ? Math.round(st.textSize * 1.6) : 0;
  return { modules, modulePx, W: st.sizePx, H: st.sizePx + textPx };
}

8.2 Canvas 路径

renderCanvas(row, st, scale) → {canvas, qr}。绘制顺序：

  1. drawModules —— 遍历矩阵画模块，支持三种样式（方形 / 圆点 / 圆角，圆角用 roundRect）
  2. drawLogo —— 居中画 LOGO，按 logoRatio × sizePx 定尺寸；logoPad 为真时先垫一块白底
  3. drawText —— 上/下绘制展示文字，超长自动缩字（fitText）

8.3 SVG 路径

renderSVG(row, st) 输出字符串。合并相邻模块为整段 <rect> 以减小体积；文字用 <text> + escapeXml() 转义。

注意 SVG 的能力差异： SVG 是纯矢量二维码，不含 LOGO、不含展示文字（设计如此）。界面上已明示这一限制。

调用方倍率用途

9ZIP 打包器实现

手写 PKZIP 格式，零第三方库。结构：本地文件头 + 数据 + 中央目录 + 中央目录结尾。

9.1 CRC32

const CRC_TABLE = (() => { ... })();   // 预计算 256 项查表
function crc32(buf){
  let c = 0xFFFFFFFF;
  for(let i = 0; i < buf.length; i++)
    c = CRC_TABLE[(c ^ buf[i]) & 0xFF] ^ (c >>> 8);
  return (c ^ 0xFFFFFFFF) >>> 0;
}

9.2 压缩 deflateRaw

async function deflateRaw(buf){
  if(typeof CompressionStream === "undefined") return null;  // → 调用方回退存储模式
  const cs = new CompressionStream("deflate-raw");
  const w = cs.writable.getWriter(); w.write(buf); w.close();
  return new Uint8Array(await new Response(cs.readable).arrayBuffer());
}

9.4 偏移量与重名

offset 累计每个本地头 + 数据的长度，写进中央目录。重名文件自动追加 (2)、(3) 后缀，不覆盖。

10预览清晰度系统

二维码是高频黑白图形，用 CSS 强行放大一定会糊。解法是高倍率渲染 + 等比缩小。

const boxW = Math.max(240, Math.min(560, elSheet.parentElement.clientWidth - 72));
const cssScale = Math.min(1, boxW / st.sizePx);        // 显示尺寸
const showW   = Math.round(st.sizePx * cssScale);
const dpr     = window.devicePixelRatio || 1;
const renderScale = Math.min(4, Math.max(2, dpr));     // 渲染倍率，2×–4×

const r = renderCanvas(row, st, renderScale);          // 画布按高倍率渲染
r.canvas.style.width = showW + "px";                   // CSS 缩到显示尺寸

关键设计：sizePx 与 scale 解耦

  • st.sizePx —— 逻辑尺寸（用户设定的输出边长）
  • scale —— 渲染倍率（只影响预览画布的像素量）

旧实现用固定 1× 渲染再 CSS 放大 → 模糊；现在按 min(4, max(2, dpr)) 渲染，像素量提升 4–16 倍后降采样，放大看也锐利。

11性能分析与量级

在 Node + DOM 桩环境下实测（真机通常更快，仅作量级参考）：

操作规模耗时单条
generateQR（URL，ECC M）1000 条~500 ms0.50 ms
generateQR（中文，ECC H）1000 条~955 ms0.96 ms
renderSVG500 条~255 ms0.51 ms
renderCanvas（scale=4）500 条~280 ms0.56 ms
parseTextRows1000 行~1.5 ms—
parseTextRows10000 行~10 ms—

buildZip500 个 SVG~300 ms—

结论

  • 瓶颈只在 QR 编码本身；ECC H 约为 M 的两倍耗时（纠错码字更多）
  • 解析与 CRC 可忽略不计
  • 1000 条规模「生成 + 渲染 + 打包」整链 < 1 秒

主线程阻塞的缓解措施

  • exportZip 按 CHUNK = 20 分批 await sleep(0) 让出主线程，同时更新进度条
  • renderList 对 > 500 条只渲染前 500 项（LIMIT = 500），导出不受影响
  • debounce 包裹文本域输入，避免每次按键都全量重解析 + 重绘

12已知问题与待办

12.1 设计上的取舍（非缺陷）

  • SVG 不含 LOGO 与文字 —— 矢量输出保持纯粹，交由下游排版
  • 无 undo 栈 —— 数据整理按钮直接改写文本域，可用 复制数据 先备份
  • 旧浏览器 ZIP 不压缩 —— 回退存储模式，体积变大但可解压

12.2 潜在风险点

  • 超大 LOGO（接近 25%）+ 低容错率 = 可能扫不出。UI 已提示「建议配 H 容错」
  • CSV 模板在 Excel 直接双击时，个别环境中文可能乱码（BOM 已加；必要时用「从文本导入」并选 UTF-8）

12.3 可优化方向

  • 把 generateQR 放进 Web Worker，彻底消除大数据集的界面卡顿
  • 增加二维码「批量预览缩略图墙」
  • 支持从粘贴板图片直接取 LOGO

  • 用 DOM 桩 + new Function(...) 执行；测试代码要注入到 IIFE 内最后的 })(); 之前，否则拿不到内部作用域
  • Node 22 里 globalThis.navigator 只读；"use strict" 下隐式全局会抛错
  • canvas 桩记得补 arcTo 等方法
